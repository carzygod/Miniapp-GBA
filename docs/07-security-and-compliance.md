# 安全、隐私与合规开发文档

版本：1.0  
状态：规划基线  
服务端环境：Ubuntu 22.04 LTS 裸机

## 1. 基本原则

- 模拟器开源许可不等于 ROM 获得授权。
- 服务默认不上传、不索引、不分发用户 ROM。
- 本地优先，云能力需要登录和明确授权。
- 所有文件、网络输入和 WASM 边界都视为不可信。
- 服务端只授予运行所需的最小文件、数据库和网络权限。
- 不通过容器或虚拟化替代操作系统权限、systemd 沙箱和应用安全设计。

## 2. 上线前置条件

在开始公开发布流程前必须完成：

1. 确认普通小程序或小游戏类目及所需主体资质。
2. 向平台预咨询模拟器、用户导入 ROM 和云存档功能是否允许。
3. 对上线地区的游戏出版、未成年人保护、内容和数据规则完成法律评估。
4. 准备软件著作权、开源许可证清单和所有自有视觉/音频素材权属证明。
5. 确认不提供任天堂官方 BIOS、商业 ROM、ROM 搜索或第三方下载入口。
6. 在用户协议中明确内容来源责任，但不得以协议替代平台和开发者自身义务。

如果无法确认 ROM 功能可审核，不得通过改名、隐藏入口或远程开关规避审核。

## 3. 开源许可证

### 3.1 mGBA

- mGBA 使用 MPL-2.0。
- 保留版权和许可证文本。
- 分发修改后的受覆盖文件时，提供对应源码及获取方式。
- `core/UPSTREAM.md` 记录固定 commit 和所有修改。
- 检查 mGBA 内含第三方库的许可证和编译启用情况。

### 3.2 gbajs/gbajs2

- 如果 POC 或测试工具复制其 BSD-2-Clause 代码，保留版权、条件和免责声明。
- 正式核心不应无意混合 gbajs 与 mGBA 源码，避免来源和许可证边界模糊。

### 3.3 构建产物

- 小程序“关于”页提供核心名称、版本、许可证和源码获取方式。
- 发布包生成 SBOM，列出 npm、Go、C/C++ 依赖、版本、许可证和来源。
- 禁止把开发测试 ROM、生产密钥、源码映射或调试符号误打入发布包。

## 4. 威胁模型

### 4.1 保护资产

- 用户电池存档和状态存档。
- 微信身份映射和会话令牌。
- 服务端 AppSecret、签名密钥和上传私钥。
- 数据库、blob 数据盘和备份。
- 小程序发布权限。
- 核心和业务代码供应链完整性。

### 4.2 主要威胁

- 恶意 ROM、补丁或压缩包触发解析器越界、内存耗尽或无限循环。
- 路径穿越导致覆盖其他存档或服务端文件。
- 伪造 userId/romId 读取其他用户存档。
- 重放旧上传覆盖较新云存档。
- 日志、诊断包或错误响应泄露 token、openid 或本地路径。
- 上传超大文件耗尽磁盘、内存和连接。
- 被盗发布私钥上传恶意小程序版本。
- 依赖包或上游核心被篡改。
- 运维人员绕过审计读取用户数据。

## 5. 客户端文件安全

### 5.1 输入限制

- `.gba` 原始文件最大 32 MiB。
- 首版拒绝未知扩展名；MIME 只作提示，不作信任依据。
- Header 校验失败时默认拒绝，诊断开关不得在生产开放。
- 所有整数长度在加法、乘法和内存分配前检查溢出。
- 哈希和解析采用分块读取，避免为同一文件创建多份完整副本。

### 5.2 压缩包

- 限制压缩包大小、条目数、单条目大小、总解压大小和压缩比。
- 规范化路径后仍包含 `..`、绝对路径、盘符或 NUL 的条目全部拒绝。
- 不创建符号链接、硬链接、设备文件或可执行文件。
- 解压目录使用随机临时 ID，不采用条目名作为顶层路径。
- 解析失败或超时后清理临时文件，并记录不含文件正文的错误。

### 5.3 WASM 隔离

- WASM 只获得明确 imports，不提供任意网络或文件接口。
- JS 传入的 ptr/len 在 C 边界重复验证。
- 生产构建不导出任意 malloc、内存浏览器或调试写入接口；若 ABI 必须导出分配函数，只允许包装层访问。
- 核心进入异常状态后不继续执行帧循环，销毁实例并要求重新加载。
- 核心版本升级必须运行恶意/损坏 ROM 回归集。

## 6. 身份与会话

### 6.1 微信登录

- 客户端只获取一次性 code，并通过 HTTPS 发送给服务端。
- AppSecret 只存在 Ubuntu 服务端权限受控文件中。
- openid/unionid 不返回给客户端，不写普通访问日志。
- 数据库保存经过密钥化哈希或受控映射的微信主体标识。

### 6.2 Token

- access token 短期有效，建议 15 分钟。
- refresh session 建议最长 30 天并支持设备级撤销。
- refresh token 在数据库只保存密码学摘要。
- token 包含 audience、issuer、subject、session ID、签发和过期时间。
- 签名密钥支持双密钥滚动；当前和上一密钥短期并存。
- 客户端 token 只存平台安全存储，不进入 URL、日志、错误信息或 Redux/React 开发快照。

## 7. 授权

- 所有存档查询首先限定当前认证 user ID，再匹配 ROM ID。
- 服务端忽略客户端传入的 user ID。
- 管理接口使用独立监听地址或网络 ACL，不与公网用户路由共享授权逻辑。
- 数据删除、历史恢复和管理员操作写 append-only 审计事件。
- blob digest 不能直接作为公开下载能力；下载必须经过用户授权检查。
- 错误响应不区分“其他用户对象存在”和“不存在”，统一返回 404。

## 8. API 防护

- 只开放 HTTPS，TLS 1.2 及以上。
- Nginx 和 Go 层都设置 body 大小上限、header 上限、读取/写入/空闲超时。
- 上传流式写盘，不使用 `io.ReadAll` 读取不受信任 body。
- 支持 Idempotency-Key，防止移动网络重试产生重复 revision。
- revision 使用 `If-Match` 或等价字段，冲突返回 409。
- 登录、上传、下载、删除分别设置按用户/IP 的速率限制。
- CORS 对小程序 API 通常不作为主要安全边界，鉴权仍必须完整。
- 所有 SQL 参数化；路径只由服务端生成。
- 生产错误不返回 SQL、栈、绝对路径或上游微信响应正文。

## 9. 文件系统和进程权限

Ubuntu 22.04 服务端：

- API 使用专用系统用户 `minigba`，禁止登录 shell。
- 程序目录只读，blob 和临时目录分别授予最小写权限。
- Nginx 用户不能读取 AppSecret、签名密钥、数据库凭证和 blob 正文。
- PostgreSQL 业务账号只拥有应用 schema 所需权限，不是超级用户。
- systemd 启用 `NoNewPrivileges`、`PrivateTmp`、`ProtectSystem=strict`、`ProtectHome=true` 和精确 `ReadWritePaths`。
- 密钥文件权限为 root 可写、服务用户可按最小方式读取，禁止组和其他用户读取。
- 备份目录与生产 blob 目录使用不同权限和存储目标。

## 10. 隐私设计

### 10.1 最小收集

必要数据：

- 微信账号的服务端内部映射。
- 用户主动开启同步后的存档正文和元数据。
- 设备随机 ID、非精确设备显示名称、客户端和核心版本。
- 安全、同步和删除审计记录。

默认不收集：

- ROM 正文和 ROM 文件名。
- 游戏运行画面、按键序列和游戏内行为。
- 通讯录、位置、相册、麦克风或广告标识。
- 存档正文分析结果。

### 10.2 用户权利

- 查看云端保存的游戏和版本列表。
- 下载自己的存档。
- 删除单存档、单游戏或全部账号数据。
- 关闭云同步而保留本地数据。
- 生成不含身份凭证和二进制正文的诊断包。

### 10.3 日志保留

- 普通访问日志建议 14 天。
- 安全和删除审计按合规要求配置保留期限。
- 日志中的用户标识使用不可逆短哈希。
- 超期日志由 systemd timer 或 logrotate 删除，删除有监控和审计。

## 11. 数据静态保护

- 数据盘使用主机或云磁盘提供的静态加密能力；部署时记录是否启用。
- 存档对象可增加应用层 envelope encryption；若启用，密钥与数据盘分离。
- 数据库和 blob 备份必须加密，恢复密钥不得与备份放在同一位置。
- checksum 用于完整性，不替代认证加密或数字签名。
- 密钥轮换必须有文档化演练，不允许只能重建全部数据才能换钥。

## 12. 供应链安全

- npm 只使用 `npm ci` 和提交的 lockfile。
- Go 模块提交 `go.sum`，构建时验证模块校验。
- emsdk、Node、Go 下载包校验官方 SHA-256。
- mGBA 使用固定 commit，更新必须经过 diff、许可证和回归检查。
- CI 生成依赖清单、许可证报告、秘密扫描和静态分析结果。
- 生产构建在干净 Ubuntu 22.04 主机上执行，不读取开发者个人全局 npm 包。
- 小程序上传私钥放在 CI/发布主机凭证目录，权限 0600，定期轮换。

## 13. 备份与恢复安全

- `pg_dump` 和 blob 快照属于同一恢复点，记录共同 backup ID。
- 备份完成后生成清单和 SHA-256，并执行加密。
- 每月至少完成一次隔离目录恢复验证。
- 恢复演练使用脱敏或受控生产备份，恢复目录禁止被公网 API 读取。
- 删除用户数据后，备份内数据按备份保留期限自然过期；隐私政策必须说明该窗口。

## 14. 安全事件响应

事件等级：

- SEV-1：密钥泄露、跨用户读取、存档大规模破坏或恶意版本发布。
- SEV-2：局部数据丢失、可利用拒绝服务、审核下架风险。
- SEV-3：无数据影响的配置弱点或低风险依赖问题。

SEV-1 基本流程：

1. 停止受影响写路径，保留只读恢复能力。
2. 轮换 token 签名密钥、微信凭证或发布密钥。
3. 保存 journald、Nginx、数据库和发布审计证据。
4. 确定受影响用户和时间窗口。
5. 按法律、平台和隐私政策要求通知。
6. 修复、恢复、验证并形成复盘和长期行动项。

不得通过删除日志或直接覆盖生产文件来“恢复服务”。
