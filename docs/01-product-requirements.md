# MiniGBA 产品需求文档

版本：1.0  
状态：规划基线  
目标平台：微信小程序  
服务端环境：Ubuntu 22.04 LTS 裸机

## 1. 产品概述

MiniGBA 是一个微信小程序内的 GBA 模拟器前端。用户可以从微信会话文件或经授权的 HTTPS 来源导入 ROM，在本地运行游戏，并管理电池存档、即时状态存档及跨设备云存档。

产品不提供商业 ROM，不以内置或推荐盗版内容作为获客方式。模拟器核心与游戏内容相互独立；用户必须确认其对导入内容拥有合法使用权。

## 2. 产品目标

### 2.1 核心目标

- 在主流 iOS、Android 微信客户端上稳定运行合法 GBA ROM。
- 提供低延迟、多点触控、横竖屏均可操作的完整虚拟按键。
- 保证本地存档可靠，异常退出后最大限度降低进度丢失风险。
- 使用微信身份实现跨设备云存档、历史版本恢复和冲突保护。
- 让用户能明确查看、导出和删除自己的 ROM、存档及云端数据。

### 2.2 成功指标

- 首次导入到进入游戏的成功率不低于 98%，不含无效、加密或不支持的文件。
- 已验证 ROM 集合的启动成功率不低于 95%。
- 目标设备上稳定场景平均帧率不低于 58 FPS，P95 帧时间不高于 20 ms。
- 30 分钟连续运行期间音频欠载不超过 1 次，且不得持续爆音或失声。
- 本地电池存档写入及恢复成功率达到 100% 的自动化测试样本要求。
- 正常网络条件下云存档同步成功率不低于 99.5%。
- 崩溃、强制退出或网络中断测试中不得静默覆盖较新的存档。

### 2.3 非目标

- 不追求复刻 gbajs3 的桌面窗口、拖拽面板和浏览器 PWA 体验。
- 不承诺所有 ROM Hack、非标准卡带硬件或未授权修改版均可运行。
- 不在首版提供 ROM 在线社区、排行榜、直播、对战或用户内容分享。
- 不在首版提供作弊码、倒带、录像、联机线缆和外接手柄保证。

## 3. 用户角色

### 3.1 游客

- 可以阅读隐私和版权提示。
- 可以导入 ROM、使用本地游戏和本地存档。
- 无法使用云存档。

### 3.2 已登录用户

- 拥有游客全部能力。
- 可以启用自动云同步、查看云端版本、恢复或删除云存档。
- 可以在新设备上根据 ROM hash 匹配并恢复存档。

### 3.3 运营管理员

- 仅通过独立管理接口查看服务健康和匿名统计。
- 可以处理用户数据删除工单和封禁滥用请求。
- 无权查看 ROM 内容；系统默认不上传 ROM。
- 对存档内容的访问必须有审计记录并遵循最小权限。

## 4. 关键术语

| 术语 | 定义 |
| --- | --- |
| ROM | 用户导入的 `.gba` 游戏镜像；首版只接受未加密 GBA 文件 |
| ROM ID | ROM 原始字节的 SHA-256，小写十六进制字符串 |
| 电池存档 | 游戏卡带持久化数据，对应 SRAM、Flash 或 EEPROM，扩展名 `.sav` |
| 状态存档 | 模拟器完整运行状态，依赖核心版本和 ROM 内容 |
| 自动恢复点 | 按时间间隔以及进入后台时生成的专用状态存档 |
| 云存档 | 上传到服务端的电池存档、状态存档和版本元数据，不包含 ROM |
| revision | 云端存档单调递增版本号，用于并发更新和冲突检测 |

## 5. 信息架构

小程序包含以下一级页面：

1. 游戏库：首页，展示本地 ROM、最近游戏、存档状态和导入入口。
2. 播放器：画面、虚拟控制、快捷菜单、暂停和状态提示。
3. 存档中心：按游戏查看本地/云端电池存档、状态槽和历史版本。
4. 设置：显示、音频、控制布局、同步、存储、隐私和诊断。
5. 关于与合规：许可证、隐私政策、用户协议、版权声明和数据删除。

## 6. 核心用户流程

### 6.1 首次导入并游玩

1. 用户打开游戏库，阅读并确认首次版权提示。
2. 用户选择“从微信文件导入”。
3. 系统限制扩展名、大小，读取文件头并计算 SHA-256。
4. 系统检查本地是否已有相同 ROM；重复内容不再次占用空间。
5. 系统创建游戏索引并进入详情页。
6. 用户点击开始，系统加载匹配的电池存档和可用自动恢复点。
7. 用户选择继续自动恢复点、仅加载电池存档或重新开始。
8. 用户进入播放器，音频须在首次明确触摸后启动。

### 6.2 正常退出及恢复

1. 用户打开快捷菜单或小程序进入后台。
2. 模拟器暂停，释放所有按键状态。
3. 系统拉取最新电池存档，写临时文件并校验。
4. 临时文件原子替换正式存档，并保留上一成功版本。
5. 若开启自动恢复点，则写入自动状态存档。
6. 若开启云同步且用户在线，则进入异步上传队列。
7. 下次启动时根据校验和和元数据选择最新有效版本。

### 6.3 新设备云恢复

1. 用户使用微信登录。
2. 用户导入与旧设备相同的 ROM。
3. 系统按 ROM ID 查询云端存档，不使用文件名匹配。
4. 展示云端更新时间、设备、游戏内存档大小和历史版本。
5. 用户确认后下载，校验 SHA-256，再写入本地。
6. 若本地已有不同版本，必须保留本地冲突副本，不允许静默覆盖。

## 7. 功能需求

### 7.1 启动、身份和用户协议

- `FR-ACC-001 P0`：游客无需登录即可使用所有本地能力。
- `FR-ACC-002 P0`：云同步前必须通过 `wx.login` 建立服务端会话；客户端不得持有微信 AppSecret。
- `FR-ACC-003 P0`：首次导入 ROM 前展示版权确认，确认版本和时间记录在本地。
- `FR-ACC-004 P0`：首次云同步前展示隐私说明和云端保存的数据类型。
- `FR-ACC-005 P1`：用户可以退出登录；退出不会自动删除本地文件。
- `FR-ACC-006 P0`：用户可以提交云端数据删除请求并查看处理状态。

### 7.2 ROM 导入与游戏库

- `FR-ROM-001 P0`：支持通过微信会话文件选择器导入单个 `.gba` 文件。
- `FR-ROM-002 P0`：支持从已配置的合法 HTTPS 域名下载授权 ROM；响应必须校验状态码、长度和内容摘要。
- `FR-ROM-003 P0`：首版 ROM 原始大小上限为 32 MiB；超限文件在完整读取前拒绝。
- `FR-ROM-004 P0`：导入时检查扩展名、GBA Header、Nintendo Logo 区域、文件大小和 SHA-256；Header 异常可提示风险，但不得仅凭文件名放行。
- `FR-ROM-005 P0`：相同 ROM ID 只保存一份文件，允许用户为本地条目修改显示名称。
- `FR-ROM-006 P0`：游戏库显示标题、最后游玩时间、本地存档状态、云同步状态和存储占用。
- `FR-ROM-007 P0`：删除 ROM 前说明存档是否一并删除；默认保留存档。
- `FR-ROM-008 P1`：支持重新扫描索引、修复丢失条目并隔离校验失败文件。
- `FR-ROM-009 P1`：支持 `.zip` 单 ROM 包；必须防止 Zip Slip、压缩炸弹、多 ROM 歧义和超限解压。
- `FR-ROM-010 P2`：支持 IPS、UPS、BPS 补丁，以“原 ROM hash + 补丁 hash”生成独立游戏身份。

### 7.3 模拟器运行

- `FR-EMU-001 P0`：支持 GBA ARM/Thumb、视频、音频、RTC、SRAM、Flash 和 EEPROM 基本能力。
- `FR-EMU-002 P0`：启动前加载对应 ROM ID 的电池存档，不允许跨 ROM 自动复用。
- `FR-EMU-003 P0`：播放器支持暂停、继续、软复位和安全退出。
- `FR-EMU-004 P0`：小程序进入后台、来电中断、页面卸载或音频中断时自动暂停。
- `FR-EMU-005 P0`：恢复前清空所有虚拟键，防止方向键或功能键卡住。
- `FR-EMU-006 P0`：核心异常必须停止调度、保存可恢复数据并显示错误编号，不得形成无限崩溃循环。
- `FR-EMU-007 P1`：支持 2x、3x、4x 快进；快进期间允许自动静音或限制音频同步。
- `FR-EMU-008 P1`：提供帧跳过自动模式，但默认关闭。
- `FR-EMU-009 P1`：支持 RTC 使用系统时间；检测设备时间大幅回拨并给出提示。

### 7.4 画面

- `FR-VID-001 P0`：以 240 x 160 为核心原始分辨率，保持 3:2 比例，不得拉伸。
- `FR-VID-002 P0`：竖屏时画面位于控制区上方；横屏时画面优先占据安全区域中央。
- `FR-VID-003 P0`：适配刘海、圆角、状态栏和微信胶囊按钮安全区。
- `FR-VID-004 P0`：提供“锐利像素”和“平滑缩放”两种模式。
- `FR-VID-005 P1`：显示帧率开关只用于诊断，默认关闭。
- `FR-VID-006 P1`：支持截图保存到小程序文件系统，导出到相册前单独申请权限。

### 7.5 音频

- `FR-AUD-001 P0`：首次用户交互后初始化 WebAudioContext，未获得播放能力时允许静音运行。
- `FR-AUD-002 P0`：支持音量 0% 至 100% 和一键静音。
- `FR-AUD-003 P0`：进入后台时暂停音频，返回前台后由用户交互恢复。
- `FR-AUD-004 P0`：音频环形缓冲发生欠载或溢出时记录计数，不能阻塞模拟器主循环。
- `FR-AUD-005 P1`：提供“低延迟/稳定”缓冲档位；变更后在下次启动核心时生效。

### 7.6 虚拟控制

- `FR-CTL-001 P0`：提供 Up、Down、Left、Right、A、B、L、R、Start、Select。
- `FR-CTL-002 P0`：十字键支持按住滑动换向和有效斜向组合。
- `FR-CTL-003 P0`：方向键与 A/B、L/R 必须支持多点同时按下。
- `FR-CTL-004 P0`：TouchEnd、TouchCancel、页面隐藏和暂停均释放相应按键。
- `FR-CTL-005 P0`：触控区域不得触发页面滚动、缩放或下拉刷新。
- `FR-CTL-006 P1`：用户可以调整按键位置、大小、间距和透明度，并恢复默认布局。
- `FR-CTL-007 P1`：支持左手、右手和横屏预设。
- `FR-CTL-008 P1`：支持按键震动反馈开关；不支持的设备静默降级。
- `FR-CTL-009 P1`：快捷菜单提供暂停、保存状态、加载状态和安全退出，不与 GBA 键位复用。

### 7.7 本地电池存档

- `FR-SAVE-001 P0`：核心报告电池存档变更后使用防抖写入，默认最长 5 秒内落盘。
- `FR-SAVE-002 P0`：进入后台和安全退出时立即尝试 flush。
- `FR-SAVE-003 P0`：每个 ROM 保留正式文件、上一成功版本和写入中的临时文件。
- `FR-SAVE-004 P0`：写入后重新读取并验证大小和 SHA-256，成功后才更新 manifest。
- `FR-SAVE-005 P0`：发现正式文件损坏时自动尝试上一成功版本，并向用户报告恢复结果。
- `FR-SAVE-006 P0`：用户可以导入和导出 `.sav`；导入前自动备份当前版本。
- `FR-SAVE-007 P0`：存档类型和预期容量由核心报告，不以文件扩展名推断。

### 7.8 即时状态存档

- `FR-STATE-001 P0`：提供至少 5 个手动状态槽和 1 个自动恢复槽。
- `FR-STATE-002 P0`：状态文件记录 ROM ID、核心构建 ID、格式版本、创建时间和校验和。
- `FR-STATE-003 P0`：核心版本不兼容时禁止直接加载，并允许用户删除或导出文件。
- `FR-STATE-004 P0`：加载状态前暂停模拟器；失败后保持原运行状态或安全重启，不得部分恢复。
- `FR-STATE-005 P1`：自动恢复点默认每 60 秒生成一次，并在进入后台时生成；用户可关闭。
- `FR-STATE-006 P1`：状态槽展示截图预览，但截图失败不影响状态保存。

### 7.9 云存档

- `FR-CLOUD-001 P0`：只有已登录且明确开启同步的用户才上传数据。
- `FR-CLOUD-002 P0`：默认自动同步电池存档；状态存档同步由用户单独开启。
- `FR-CLOUD-003 P0`：云端对象以用户 ID、ROM ID、存档类型和槽位隔离。
- `FR-CLOUD-004 P0`：上传使用 base revision；服务端发现版本不一致时返回冲突，不执行覆盖。
- `FR-CLOUD-005 P0`：冲突时保留本地、云端两个版本，并提供时间、设备和校验和信息。
- `FR-CLOUD-006 P0`：离线写入进入持久同步队列，网络恢复后按 ROM 串行重试。
- `FR-CLOUD-007 P0`：服务端至少保留最近 10 个电池存档版本或最近 30 天版本，以先达到者为准。
- `FR-CLOUD-008 P0`：下载后必须验证内容长度和 SHA-256，再提交到本地存档仓库。
- `FR-CLOUD-009 P0`：用户可删除单个云存档、某个游戏全部云数据或账号全部云数据。
- `FR-CLOUD-010 P1`：展示最近同步时间、状态、失败原因和手动重试入口。

### 7.10 设置、诊断与存储管理

- `FR-SET-001 P0`：设置按微信用户隔离；未登录时使用本地匿名配置。
- `FR-SET-002 P0`：提供显示、音频、控制、存档、云同步和隐私分类。
- `FR-SET-003 P0`：存储页分别显示 ROM、电池存档、状态存档、截图和临时文件占用。
- `FR-SET-004 P0`：清理缓存不得删除正式存档；危险删除必须二次确认。
- `FR-DIAG-001 P1`：诊断页显示小程序版本、基础库版本、设备摘要、核心构建 ID、平均 FPS、音频欠载和最近错误。
- `FR-DIAG-002 P1`：用户可以生成脱敏诊断包；不得包含 ROM、存档正文、openid、令牌和路径中的用户标识。

## 8. 页面详细要求

### 8.1 游戏库

- 顶部仅保留标题、搜索和导入按钮，不展示营销 Hero。
- ROM 使用紧凑列表或网格，必须能快速识别最近游戏和同步状态。
- 空状态提供导入动作、版权提示入口，不展示内置商业游戏。
- 长按或更多菜单包含重命名、存档、存储详情和删除。

### 8.2 播放器

- 画面是首要视觉区域，工具栏不得遮挡画面。
- 竖屏控制区固定高度，避免按键按下状态引发布局位移。
- 横屏使用安全区和绝对布局，但必须针对窗口尺寸重新计算。
- 快捷菜单打开时模拟器立即暂停；关闭菜单后用户主动点击继续。
- 同步、保存和错误状态使用短暂非阻塞提示；危险操作使用确认对话框。

### 8.3 存档中心

- 电池存档与状态存档分区显示，避免用户混淆。
- 每个版本显示来源设备、时间、大小、核心版本和校验状态。
- 恢复旧版本前自动生成当前版本备份。
- 冲突版本不得仅以“新的/旧的”描述，必须展示可比较元数据。

## 9. 非功能需求

### 9.1 性能

- `NFR-PERF-001`：目标设备稳定场景平均帧率至少 58 FPS。
- `NFR-PERF-002`：普通速度下核心单帧 P95 执行时间不高于 12 ms。
- `NFR-PERF-003`：触摸事件到核心按键位图更新 P95 不高于 35 ms。
- `NFR-PERF-004`：连续运行 30 分钟内存不得持续单调增长超过 20%。
- `NFR-PERF-005`：首屏不加载 WASM；进入播放器分包后才加载核心。

### 9.2 可靠性

- `NFR-REL-001`：任何单次存档写入失败不得破坏上一成功版本。
- `NFR-REL-002`：网络失败不得阻塞本地游玩和本地存档。
- `NFR-REL-003`：服务进程重启后同步队列请求必须保持幂等。
- `NFR-REL-004`：API 月度目标可用性为 99.9%，计划维护除外。

### 9.3 安全和隐私

- `NFR-SEC-001`：所有外部接口只允许 HTTPS。
- `NFR-SEC-002`：访问令牌不写日志、不进入 URL、不进入诊断包。
- `NFR-SEC-003`：所有文件上传都验证所有权、类型、大小、摘要和存储路径。
- `NFR-SEC-004`：云端不得默认接收或保存 ROM。
- `NFR-SEC-005`：用户数据删除操作可审计、可重试并有完成状态。

### 9.4 可维护性

- `NFR-MNT-001`：模拟器核心、微信平台适配、业务 UI 和云 API 必须保持独立模块。
- `NFR-MNT-002`：C/WASM ABI 采用显式版本，不允许依赖 Emscripten 私有生成符号。
- `NFR-MNT-003`：数据库变更只通过版本化迁移执行。
- `NFR-MNT-004`：生产构建必须可从锁文件和固定工具版本重复生成。

## 10. 发布验收

首个正式版本必须满足：

- 所有 P0 需求完成，P1 未完成项有明确延期记录。
- 至少 20 个合法 homebrew/测试 ROM 覆盖 CPU、视频、音频、RTC、SRAM、Flash、EEPROM。
- iOS、Android 各至少 3 档设备通过 30 分钟稳定性测试。
- 强制结束微信、切后台、来电、断网、服务器 5xx、磁盘不足和冲突同步场景通过。
- 相同 ROM 重命名后仍能正确匹配存档；不同 ROM 同名时不得串档。
- 隐私政策、用户协议、开源许可证、ROM 版权说明和数据删除流程完成审核。
- Ubuntu 22.04 全新主机部署演练和回滚演练通过。
